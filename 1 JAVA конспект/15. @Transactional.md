Аннотация `@Transactional` в Spring — это мощный инструмент, который используется для **управления транзакциями** в приложениях, работающих с базой данных.

---

## 🔹 Что такое транзакция?

Транзакция — это **последовательность операций, которая либо выполняется целиком, либо не выполняется вообще**. Это обеспечивает **атомарность** — важное свойство при работе с БД.

### Пример:
```java
public void transferMoney(Account from, Account to, BigDecimal amount) {
    withdraw(from, amount);  // списываем
    deposit(to, amount);     // начисляем
}
```

Если произойдёт ошибка после `withdraw()`, но до `deposit()`, мы получим **неконсистентное состояние БД**. Транзакция нужна, чтобы при ошибке **откатить всё назад**.

---

## 🟢 Основная идея `@Transactional`

```java
@Transactional
public void doSomething() {
    // весь метод выполняется в рамках одной транзакции
}
```

- Откроется транзакция перед методом.
    
- Если всё прошло успешно — будет **commit**.
    
- Если выброшено **непойманное исключение (runtime)** — будет **rollback**.
    

---

## 🛠 Где можно ставить `@Transactional`

- На метод класса:
```java
@Transactional
public void saveUser(User user) {...}
```

- На весь класс (тогда применяется ко всем методам):
```java
@Transactional
public class UserService {...}
```
    
- Также можно указать дополнительные параметры:
    

---

## ⚙️ Настройки `@Transactional`

### Примеры:

```java
@Transactional(
    propagation = Propagation.REQUIRED,
    isolation = Isolation.READ_COMMITTED,
    rollbackFor = Exception.class,
    readOnly = false
)
```

### 🔸 Propagation — как вести себя внутри другой транзакции:

|Тип|Описание|
|---|---|
|`REQUIRED` (по умолчанию)|Если есть текущая транзакция — использовать её, иначе создать новую|
|`REQUIRES_NEW`|Всегда создать новую транзакцию|
|`NESTED`|Вложенная транзакция (не всегда поддерживается)|
|`SUPPORTS`|Использовать текущую транзакцию, если она есть|
|`NOT_SUPPORTED`|Выполнить вне транзакции|
|`NEVER`|Ошибка, если есть транзакция|
|`MANDATORY`|Ошибка, если нет активной транзакции|

---

### 🔸 Isolation — уровень изоляции (борьба с конкурентным доступом):

[[16. Уровни изоляции транзакций]]

|Уровень|Поведение|
|---|---|
|`DEFAULT`|Зависит от СУБД|
|`READ_COMMITTED`|Видим только зафиксированные данные|
|`READ_UNCOMMITTED`|Видим даже незакоммиченные (опасно!)|
|`REPEATABLE_READ`|Повторный `SELECT` вернёт то же|
|`SERIALIZABLE`|Самый строгий, блокировка всего|

---

### 🔸 rollbackFor / noRollbackFor

```java
@Transactional(rollbackFor = CustomException.class)
```

По умолчанию Spring **делает rollback только на `RuntimeException` и `Error`**. Если тебе нужно откатиться при `CheckedException`, то указывай явно через `rollbackFor`.

---

### 🔸 readOnly

```java
@Transactional(readOnly = true)
```

- Для методов, которые только читают из базы.
    
- Это **оптимизация**: БД может использовать только чтение без блокировок.

## ⚠️ Важные подводные камни

### 1. Вызов метода внутри самого класса (self-invocation)

```java
public class MyService {
    @Transactional
    public void outer() {
        inner(); // ⚠️ транзакция НЕ будет работать!
    }

    @Transactional
    public void inner() {
        // не обернётся в прокси, аннотация проигнорируется
    }
}
```

Решение: вызывать через `ApplicationContext`, либо выносить во внешний бин.

---

### 2. `@Transactional` работает только на `public` методах

- Внутренние `private` и `protected` методы не проксируются — аннотация будет проигнорирована.
    

---

### 3. Проксирование (`AOP`)

Spring использует **прокси** (обычно JDK или CGLIB), чтобы обернуть вызовы транзакций. Важно понимать, что:

- Вызов происходит **через Spring-контекст**,
    
- Иначе механизм не сработает (см. пункт 1).
    

---

## 💡 Резюме

|Сценарий|Что нужно|
|---|---|
|Только чтение данных|`@Transactional(readOnly = true)`|
|Вложенные вызовы, каждый должен быть откатным|`REQUIRES_NEW`|
|Обычная работа с транзакцией|`REQUIRED` по умолчанию|
|Выход за рамки транзакции|`NOT_SUPPORTED` или `NEVER`|
