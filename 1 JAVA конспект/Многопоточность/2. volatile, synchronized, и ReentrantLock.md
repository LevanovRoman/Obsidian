### ✅ `volatile`

**Что делает:**  
Гарантирует **видимость изменений** переменной между потоками.

**Особенности:**

- **Не** обеспечивает атомарность операций.
    
- Только для **одиночных переменных**.
    
- Быстрее, чем `synchronized`, но с ограниченным применением.
    
- Используется, например, для флагов (`isRunning`, `stopThread` и т.п.).
```java
private volatile boolean running = true;
```

---

### ✅ `synchronized`

**Что делает:**  
Обеспечивает **монитор (lock)** на метод или блок кода — **гарантирует атомарность и видимость**.

**Особенности:**

- Простой синтаксис (`synchronized` блоки или методы).
    
- Менеджмент блокировок происходит автоматически.
    
- Может привести к блокировкам (deadlocks), если неаккуратно использовать.
    
- Медленнее, чем `volatile`, но универсальнее.

```java
synchronized(this) {
    // потокобезопасный доступ к общим данным
}
```

---

### ✅ `ReentrantLock`

**Что делает:**  
Более гибкий и мощный механизм блокировки, чем `synchronized`.

**Особенности:**

- **Ручное управление** блокировкой (`lock()` / `unlock()`).
    
- Поддерживает **попытку захвата блокировки с тайм-аутом**, **прерываемость**, **условия (Conditions)**.
    
- Можно **справляться с дедлоками** более элегантно.
    
- Требует явного вызова `unlock()`, желательно в `finally`.

```java
private final ReentrantLock lock = new ReentrantLock();

lock.lock();
try {
    // критическая секция
} finally {
    lock.unlock();
}
```

---

### 🆚 Сравнение

|Свойство|`volatile`|`synchronized`|`ReentrantLock`|
|---|---|---|---|
|Видимость|✅|✅|✅|
|Атомарность|❌|✅|✅|
|Блокировка|❌|Автоматическая|Явная (`lock()/unlock()`)|
|Гибкость|❌|❌|✅|
|Возможность прерывания|❌|❌|✅|
|Поддержка условий|❌|❌|✅ (`Condition`)|
