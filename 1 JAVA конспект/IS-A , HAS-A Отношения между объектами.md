## 🧬 1. Отношение **IS-A** (наследование / реализация)

**IS-A** означает, что **один объект является разновидностью другого**.

Это реализуется через:

- `extends` — при **наследовании класса**
    
- `implements` — при **реализации интерфейса**
    
---
### 🔧 Примеры IS-A:
```java
class Animal { }
class Dog extends Animal { }       // Dog IS-A Animal
```

```java
interface Flyable {
    void fly();
}
class Bird implements Flyable {    // Bird IS-A Flyable
    public void fly() { System.out.println("Летит"); }
}
```

### 📌 IS-A = подтип / обобщение

- `ArrayList IS-A List`
    
- `Integer IS-A Number`
    
- `Manager IS-A Employee`
    

🧠 **IS-A** — это всегда отношение **наследования**. Используется, когда класс должен **унаследовать поведение** родителя и быть **взаимозаменяемым** с ним.

---

## 🧳 2. Отношение **HAS-A** (композиция / агрегация)

**HAS-A** означает, что **один объект содержит другой**.
Это реализуется через **поля внутри класса**.
📌 HAS-A — это отношение **"часть-целое"**, часто реализуется через **композицию** (или агрегацию, если слабее связь).
## 🔄 Сравнение IS-A и HAS-A

|Характеристика|IS-A|HAS-A|
|---|---|---|
|Что означает|Объект **является** другим|Объект **содержит** другой|
|Отношение|Наследование / реализация|Композиция / агрегация|
|Используется когда|Нужно переиспользовать логику|Нужно добавить поведение|
|Ключевые слова|`extends`, `implements`|поля внутри класса|
|Пример|`Dog extends Animal`|`Car has Engine`|

---

## 💡 Когда что использовать?

|Задача|Подход|
|---|---|
|Объект **является подтипом** другого|IS-A|
|Объект **содержит** другой объект|HAS-A|
|Нужно **расширить** поведение|IS-A|
|Нужно **использовать функциональность другого объекта**|HAS-A|
### 📌**Ассоциация**, **Агрегация** и **Композиция** 

— всё это про отношения **"один объект связан с другим"**, но на **разной глубине и силе связи**.

## 🔹 1. **Ассоциация** (Association)

**Ассоциация** — это **общее понятие**: один объект **знает о другом** и **может взаимодействовать с ним**.

👉 Это просто **ссылка одного объекта на другой**.
```java
class Driver {
    private String name;
}

class Car {
    private Driver driver;  // Car "знает" своего водителя → ассоциация
}
```

📌 Характеристики:

- Направленная или двусторонняя
    
- Может быть один-к-одному, один-ко-многим и т.д.
    
- Объекты **могут существовать независимо**
    

---

## 🔸 2. **Агрегация** (Aggregation) — "слабая связь"

Агрегация — это **частный случай ассоциации**, когда один объект **содержит другой**, но **оба могут существовать независимо**. Это **“has-a”**-отношение, но **слабое**.
```java
class Department {
    private List<Employee> employees;  // Агрегация
}

class Employee {
    private String name;
}
```

📌 Особенности:

- `Department` **имеет** `Employee`, но сотрудники могут существовать **вне отдела**
    
- Отдел **не владеет** сотрудниками полностью
    
- Если удалить `Department` — `Employee` может остаться
    

---

## 🔹 3. **Композиция** (Composition) — "сильная связь"

Композиция — это **более сильная форма агрегации**, когда один объект **владеет** другим:  
**если внешний объект уничтожается — внутренний тоже**.

```java
class House {
    private Room room;  // Композиция
}

class Room {
    private String name;
}
```

📌 Особенности:

- `Room` **не может существовать без** `House`
    
- Жизненные циклы связаны
    
- Один объект полностью **отвечает за создание и удаление** другого
    

---

## 🔄 Сравнение: Ассоциация vs Агрегация vs Композиция

|Свойство|Ассоциация|Агрегация|Композиция|
|---|---|---|---|
|Тип связи|Общая связь|"Имеет" (слабая)|"Имеет" (сильная)|
|Жизненный цикл|Независимый|Независимый|Зависимый|
|Владелец создает объект?|Не обязательно|Нет|Да|
|Уничтожение владельца удаляет зависимый?|❌|❌|✅|
|Пример|Студент и Курс|Отдел и Сотрудник|Человек и Сердце|

---

## 🔧 Примеры в коде

🟢 Ассоциация (двусторонняя)

```java
class Student {
    private Course course;
}

class Course {
    private List<Student> students;
}
```

🟡 Агрегация

```java
class Team {
    private List<Player> players;

    public Team(List<Player> players) {
        this.players = players; // внешние игроки "прикреплены"
    }
}
```

🔴 Композиция

```java
class Computer {
    private final CPU cpu = new CPU(); // создаётся внутри
    private final RAM ram = new RAM(); // создаётся внутри
}

class CPU {}
class RAM {}
```

---

## 🎯 Итог

|Тип|Связь|Кто кого создаёт|Совместное существование|
|---|---|---|---|
|Ассоциация|Любая|Не важно|Независимые объекты|
|Агрегация|"Has-a"|Обычно снаружи|Независимые объекты|
|Композиция|"Owns-a"|Владелец создаёт|Объекты живут вместе|
