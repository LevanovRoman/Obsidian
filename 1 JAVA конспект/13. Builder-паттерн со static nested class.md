## 🔨 Что такое Builder-паттерн?

Builder нужен для **удобного и пошагового создания объектов**, особенно если у объекта много полей, и не все обязательны.  
Он позволяет **избежать перегрузки конструкторов** и **повысить читаемость кода**.

---

## 🧱 Пример: класс `User` с Builder-ом
```java
public class User {
    // обязательные поля
    private final String username;
    private final String email;

    // необязательные поля
    private final String phone;
    private final int age;

    // приватный конструктор
    private User(Builder builder) {
        this.username = builder.username;
        this.email = builder.email;
        this.phone = builder.phone;
        this.age = builder.age;
    }

    // static nested builder class
    public static class Builder {
        // копии всех полей из внешнего класса
        private final String username;
        private final String email;

        private String phone;
        private int age;

        // конструктор с обязательными полями
        public Builder(String username, String email) {
            this.username = username;
            this.email = email;
        }

        // сеттеры с возвратом самого builder-а
        public Builder phone(String phone) {
            this.phone = phone;
            return this;
        }

        public Builder age(int age) {
            this.age = age;
            return this;
        }

        // финальный метод для сборки объекта
        public User build() {
            return new User(this);
        }
    }

    // для примера вывода
    @Override
    public String toString() {
        return username + " (" + email + "), age: " + age + ", phone: " + phone;
    }
}
```

---

## ✅ Использование:
```java
public class Main {
    public static void main(String[] args) {
        User user = new User.Builder("johndoe", "john@example.com")
                .age(30)
                .phone("123-456-7890")
                .build();

        System.out.println(user);
    }
}
```
📌 Благодаря `static nested class`, мы можем создать объект `Builder` без создания `User`, и удобно "цепочкой" настраивать параметры.

---

## 🔍 Почему здесь `Builder` — static nested class?

- Он **не зависит** от экземпляра `User`, а наоборот, **создаёт его**
    
- Он **логически принадлежит** классу `User`
    
- Его удобно использовать с **пошаговой настройкой**
    
- Это **инкапсулирует** логику создания и делает объект `User` **иммутабельным**
