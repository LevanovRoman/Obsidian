## 🔹 1. **Static Nested Class (статический вложенный класс)**

Объявляется с ключевым словом `static`.  
**Не имеет доступа к нестатическим членам внешнего класса.**
```java
class Outer {
    static class StaticNested {
        void display() {
            System.out.println("Внутри static nested класса");
        }
    }
}
```
🔸 Использование:

```java
Outer.StaticNested nested = new Outer.StaticNested();
nested.display();
```
---

## 🔸 Особенности

|Характеристика|Описание|
|---|---|
|`static` модификатор|Делает вложенный класс **независимым от экземпляра** внешнего класса|
|Доступ к членам внешнего класса|Имеет доступ **только к static-членам** внешнего класса|
|Не может обращаться к `this` внешнего класса|Потому что он не связан с экземпляром внешнего класса|
|Компилируется как отдельный `.class` файл|Например, `Outer$StaticNested.class`|

---

## 🔸 Пример использования в реальном коде

Допустим, у тебя есть класс `Database`, и тебе нужно описать конфигурацию подключения:
```java
class Database {
    static class Config {
        String url;
        String username;
        String password;

        Config(String url, String username, String password) {
            this.url = url;
            this.username = username;
            this.password = password;
        }
    }

    static void connect(Config config) {
        System.out.println("Connecting to: " + config.url);
    }
}
```
Использование:
```java
Database.Config config = new Database.Config(
    "jdbc:mysql://localhost:3306/mydb",
    "admin",
    "pass"
);
Database.connect(config);
```

## 🔸 Когда использовать `static nested class`?

Используй его, когда:

- Вложенный класс **логически относится к внешнему**, но **не требует доступа к его нестатическим полям**
    
- Ты хочешь **избежать зависимости** от экземпляра внешнего класса
    
- Нужно **структурировать код** и **инкапсулировать логику**, например:
    
    - DTO/конфигурации
        
    - Builder-паттерн
        
    - Хелперы, утилиты

---

## 🔸 Связь с другими классами:

- Вложенный `static` класс может содержать и `static`, и `non-static` члены.
    
- Может наследовать другие классы и реализовывать интерфейсы.
    
- Может быть `private`, `protected`, `public`, или package-private (по умолчанию).

``` java
class Outer {
    private static class Helper {
        static void assist() {
            System.out.println("Helping from nested class");
        }
    }

    void useHelper() {
        Helper.assist();
    }
}
```

## 🔸 2. **Inner Class (нестатический вложенный класс)**

Объявляется **без `static`**, и поэтому **имеет доступ ко всем полям и методам внешнего класса**, даже к `private`.

```java
class Outer {
    private String message = "Hello from Outer";

    class Inner {
        void print() {
            System.out.println(message); // доступ к private полю Outer
        }
    }
}
```
🔸 Использование:
```java
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();
inner.print();
```

📌 `Inner` **не может существовать сам по себе** — ему нужен внешний объект `Outer`, потому что он связан с его состоянием.

---

## 🔸 Что может делать Inner Class?

|Возможность|Подробности|
|---|---|
|Доступ к членам Outer|Да, ко всем, даже `private`|
|Может обращаться к `this` внешнего класса|Да: `Outer.this`|
|Может быть `private/protected/public`|Да|
|Может содержать поля и методы|Да|
|Может наследовать/реализовывать интерфейсы|Да|

---

## 🔹 Пример: Inner-класс как часть логики Outer

```java
class Car {
    private String model = "BMW";

    class Engine {
        void start() {
            System.out.println("Engine of " + model + " started.");
        }
    }
}
```

Использование:
```java
Car car = new Car();
Car.Engine engine = car.new Engine();
engine.start();
```

---
## 🔸 Особенности

### 📌 Обращение к внешнему объекту:

```java
Outer.Inner inner = outer.new Inner();
```

Ты **не можешь** просто написать `new Inner()` — нужно `outer.new Inner()`.

---

### 📌 Обращение к внешнему `this`:
```java
class Outer {
    int x = 10;

    class Inner {
        int x = 20;

        void print() {
            System.out.println("Inner x = " + x);
            System.out.println("Outer x = " + Outer.this.x); // доступ к внешнему x
        }
    }
}
```

---

## 🔸 Где используется Inner Class?

- Когда **вложенный класс должен иметь прямой доступ** к данным внешнего объекта
    
- Для **инкапсуляции вспомогательной логики**, тесно связанной с внешним объектом
    
- В GUI-приложениях (например, обработчики событий в Swing)
    
- В DSL-структурах (например, для конфигурации)

---
## 🔹 Плюсы:

✔️ Доступ ко всем членам внешнего класса  
✔️ Упрощённая логика, когда внутренний класс зависит от состояния внешнего  
✔️ Повышает инкапсуляцию, если использовать `private/protected`

## 🔻 Минусы:

❌ Всегда требует экземпляр внешнего класса  
❌ Может привести к **утечкам памяти**, если внутренний класс живёт дольше, чем нужно (например, при использовании в лямбдах или асинхронных задачах)

## 🔸 3. **Local Class (локальный класс)**

Класс, объявленный **внутри метода** или блока кода (например, в `if`/`for`).  
Он **доступен только в пределах этого блока**, как обычная локальная переменная.
Имеет доступ к **переменным метода**, если они **final или effectively final**.
```java
class Outer {
    void method() {
        int x = 10; // должна быть effectively final

        class Local {
            void print() {
                System.out.println("x = " + x);
            }
        }

        Local local = new Local();
        local.print();
    }
}
```
---

## 🔍 Особенности локального класса

|Особенность|Подробности|
|---|---|
|Объявляется внутри метода или блока|Только локально|
|Имеет доступ ко всем **полям внешнего класса**|Даже `private`|
|Имеет доступ к **локальным переменным метода**, но…|Только если они **final** или **effectively final**|
|Может быть только `final` или package-private|Нельзя использовать `public`, `private`, `protected`, `static`|

---

## 📌 Что значит **effectively final**?

Переменная считается _effectively final_, если **после инициализации она больше не изменяется**

```java
void example() {
    int x = 10; // effectively final

    class Local {
        void print() {
            System.out.println(x); // можно, потому что x не меняется
        }
    }

    // x = 15; ❌ Если раскомментировать — будет ошибка
}
```

🧱 Пример: локальный класс в методе

```java
class Calculator {
    void calculate(int a, int b) {
        final String operation = "Сложение";

        class Adder {
            int add() {
                return a + b;
            }

            void printOperation() {
                System.out.println(operation + ": " + add());
            }
        }

        Adder adder = new Adder();
        adder.printOperation();
    }
}
```

---

## 💡 Где применяются локальные классы?

- Когда нужно **временно инкапсулировать логику**
    
- Когда класс **используется только внутри одного метода**
    
- В **обработчиках событий**, **многопоточности**, **тестах**
    
- Чтобы не засорять пространство имён уровня класса
    

---

## 🔁 Сравнение с другими вложенными:

|Тип класса|Где объявляется|Доступ к членам внешнего класса|Доступ к переменным метода|
|---|---|---|---|
|Static nested|Внутри класса, static|Только static|Нет|
|Inner (нестатический)|Внутри класса|Да|Нет|
|Local|Внутри метода|Да|Только final / effectively final|
|Anonymous|В выражении (обычно с new)|Да|Только final / effectively final|

---

## ✅ Плюсы:

- Простота
    
- Инкапсуляция временной логики
    
- Удобно, когда нужен один класс на короткое время
    

## ❌ Минусы:

- Неудобен для повторного использования
    
- Иногда может мешать читаемости (если метод слишком перегружен)
---

## 🔸 4. **Anonymous Class (анонимный класс)**

**Анонимный класс** — это **безымянный подкласс или реализация интерфейса**, определённый **внутри выражения `new`**, обычно для **одноразового использования**.

Он создаётся **в момент инициализации** и **не имеет имени**, поэтому ты не можешь его использовать повторно. Это как написать весь класс «на месте».
Часто используется с лямбдами и слушателями.
🔧 Пример: реализация интерфейса `Runnable`
```java
Runnable r = new Runnable() {
    @Override
    public void run() {
        System.out.println("Анонимный класс в действии");
    }
};

r.run();
```
💡 Здесь `Runnable` реализуется на месте, без создания отдельного класса.

---
## 🔍 Особенности анонимных классов

| Особенность                                                                               | Описание                              |
| ----------------------------------------------------------------------------------------- | ------------------------------------- |
| Без имени                                                                                 | Нельзя повторно использовать          |
| Объявляется и создаётся сразу                                                             | `new Type() { ... }`                  |
| Имеет доступ ко всем членам внешнего класса                                               | В том числе `private`                 |
| Может обращаться к **локальным переменным**, если они **final** или **effectively final** | Как и локальные классы                |
| Можно реализовать **только один интерфейс** или **унаследовать только один класс**        | Множественное наследование недоступно |


## 🔁 Отличия от других вложенных классов

| Тип           | Имя  | Где объявляется | Поддерживает повторное использование? | Доступ к переменным метода |
| ------------- | ---- | --------------- | ------------------------------------- | -------------------------- |
| Static nested | Есть | В классе        | ✅                                     | ❌                          |
| Inner         | Есть | В классе        | ✅                                     | ❌                          |
| Local         | Есть | В методе        | ❌                                     | ✅ (если final)             |
| **Anonymous** | ❌    | В выражении     | ❌                                     | ✅ (если final)             |

---

## ✅ Преимущества:

- 📦 **Минимум кода** — всё "на месте"
    
- 🔁 Удобно для **одноразовых обработчиков** (UI, потоки, таймеры)
    
- 📚 Легко читается в простых случаях
    

---

## ❌ Недостатки:

- 🔒 **Нельзя повторно использовать** код
    
- 🧠 **Сложнее читать**, если логика разрастается
    
- ⚠️ Может быть неочевидно, к какому классу относится `this`

## 📌 Сравнение вложенных классов:

|Тип|`static`|Доступ к нестат. членам|Где объявляется|Когда использовать|
|---|---|---|---|---|
|Static Nested|✅|❌|В классе|Когда не нужен доступ к экземпляру внешнего|
|Inner|❌|✅|В классе|Когда нужен доступ к полям внешнего класса|
|Local|❌|✅ (final/eff. final)|В методе|Временные вспомогательные классы|
|Anonymous|❌|✅|В выражении|Для одноразовой реализации интерфейса|
